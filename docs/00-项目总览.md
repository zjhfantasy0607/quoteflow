# 00 项目总览

## 1. 项目是什么

QuoteFlow 是按《询盘报价平台_需求确认书_30工作日_V2.3》（共 31 条）定制开发的询盘报价平台：

- **B/S 云端 Web**，两个门户：采购方门户（内部员工）和供应商门户（外部供应商），权限与数据隔离。
- **中英双语**：账号级语言（zh-CN / en-US），即时切换；业务字段标签中英对照，与客户的 PPL 报价模板一致。
- 31 条一条不漏（含材料库 #31 与多次议价 #30）。需求确认书按 30 个工作日编制，但**开发不按日历排期**，按模块推进，能做多快做多快（§7）。
- 客户所在行业从 PPT 示例推断为**灯具制造**：采购灯珠（如 2835 / 0.5W / 6V / 150mA / 6500K）和灯外设（透镜、反光杯、支架、驱动电源、散热器、连接器、线材等）。演示数据按这个行业准备。

需求确认书原文、PPL 报价模板、合同模板、客户真实数据**目前都没有**。文档在这些地方给出了可替换的默认做法，汇总在 [待确认事项](待确认事项.md)。

## 2. 角色

| 角色 | 代码 | 在系统里做什么 |
|---|---|---|
| PD（产品开发） | `PD` | 建询价草稿、上传规格书和产品图、发起规格变更 |
| 采购员 | `BUYER` | 建询价、选邀请供应商、发布、催报、看比价、议价、维护供应商/材料、编辑合同 |
| 采购主管 | `PURCHASE_MANAGER` | 审批询价单、开标、定标、取消询价、审核合同 |
| 合同批准人 | `CONTRACT_APPROVER` | 批准合同（需求 #25 有"审核→批准"两步，PPT 未指定批准人，见 A-08） |
| 系统管理员 | `ADMIN` | 账号、角色权限、数据字典、系统参数、PPL 模板、邮件记录、操作日志 |
| 供应商 | `SUPPLIER` | 在门户查看受邀询价、下载规格、报价/拒绝、更新报价、回复议价 |

角色可配置（#19）：以上是预置角色，管理员可以新建角色并分配功能权限、数据权限、字段权限。详见 [05-状态机与权限](05-状态机与权限.md)。

## 3. 业务主流程

```
[采购方]                                                            [供应商]
 项目号建询价草稿 (#1)
   └─ 添加询价行：从材料库选用 (#31) / 手工 / Excel 导入 (#29)，关联材料分类 (#21)
 PD 上传规格书（PDF/XLSX/图片）和行级产品图 (#2)       —— 审批前供应商不可见
 提交审批 → 采购主管 通过/驳回(填意见) (#22)
   └─ 通过：生成正式询价号 RFQ-yyyymm-nnnn
 选择受邀供应商（按战略/优秀/普通、主营材料分类筛选）(#3, #20)
 设置截止时间并发布 ──── 自动发邀请邮件（按收件人语言）(#4) ────→ 查看询价、在线预览/下载规格（记日志）(#5)
                                                                    按 PPL 模板在线填报，或下载锁定 Excel 填好导入 (#6)
                                                                    或拒绝报价（必填原因）(#6)
                         催报邮件（手动 + 截止前自动）(#4)          截止前可反复更新，以最后一次为准，历史可查 (#9)
 ── 等待报价：采购方只看到提交状态，看不到金额（密封）(#23) ──
 截止 → 报价完成 → 采购主管开标 (#23) ──── 开标通知 ────→
 比价矩阵：各家报价、变更备注、变更高亮、可导出 (#7)
 选 ≤2 家发目标价 (#8) ──── 议价通知 ────→                          接受 / 拒绝(必填原因) / 反提案 (#30)
 多轮议价直至成交，全程留痕 (#30)                ←────────────────
 采购主管定标 1 家，其余未中标 (#10, #24) ── 中标/结果通知 ──→
 评标完成 = 询盘完成，整单只读 (#11)
 自动生成合同草稿（带询价/报价快照）→ 合同审核 → 合同批准 (#25)

 支线：PD 规格变更 → 同一询价号开新轮次 → 通知重新报价 → 旧轮次只读 (#12)
 统计：年项目数与品类、供应商响应速度、中选次数与成功率、询盘周期 (#13–17)
 报表：询报价单统计、物流报价明细、供应商积分统计与流水 (#26)
```

## 5. 范围外（明确不做）

PPT 的 27 张 UI 示意图由 AI 生成，每张的系统名和菜单都不同，还混进了 31 条以外的模块。**这些一律不做**，也不要在菜单里留入口：

- 订单管理、发货管理、对账管理、库存管理（入库/出库）、销售管理、租赁管理、设备管理
- 招投标意义上的"公开招标"、预算金额、综合得分/评分模型、质量/售后承诺打分
- 电子签章（PPT 原文："本期不做电子签，合同审批完成后以纸质签订为准"）
- 供应商准入、供应商评估/绩效、黑名单
- 站内信/消息中心（只做邮件 + 工作台待办）、移动端/小程序、SSO、ERP/金蝶对接（PPT 原文："不采用金蝶简道云租赁模块"）
- 任意格式 Excel 的智能识别（#29 明确不支持）
- 多币种换算（一张询价单只用一种币种，见 A-11）

示意图可以参考的是功能点和字段，不是布局、配色和菜单结构。界面统一按 [01-技术架构](01-技术架构.md) §5 的信息架构做。

## 7. 推进方式

不按日历排期，按模块顺序推进，能做多快做多快、能做多少做多少。一个模块的完成标准：模块文档的验收项全部满足、`npm run verify` 全绿、[进度](进度.md) 已更新。

| 顺序 | 模块 | 做完后能看到什么 |
|---|---|---|
| 1 | M00 工程基座 | 前后端能启动，中英文即时切换 |
| 2 | M01 认证与权限 | 6 个角色登录，菜单随权限变化 |
| 3 | M02 系统设置与基础设施 | 字典、参数、邮件记录、文件预览、找回密码 |
| 4 | M03 材料分类与材料库 | 分类树、材料库、Excel 导入导出 |
| 5 | M04 供应商管理 | 按战略/优秀/普通过滤，门户账号激活 |
| 6 | M05 PPL 模板引擎 | 70 列模板与变体 |
| 7 | M06 询价单与审批 | 建单 → 审批 → 正式询价号 |
| 8 | M07 邀请发布与邮件通知 | 发布后供应商收到邀请邮件 |
| 9 | M08 供应商门户 | 供应商查看/下载规格并留痕 |
| 10 | M09 报价填报与版本 | 在线 / Excel 报价、多版本、拒绝 |
| 11 | M10 状态机、密封与开标 | 密封视图、截止、开标 |
| 12 | M11 比价与议价 | 比价矩阵、导出、多轮议价 |
| 13 | M12 定标与询盘完成 | 定标、整单只读、合同草稿 |
| 14 | M13 规格变更 | 新轮次、规格对比 |
| 15 | M14 合同管理 | 合同审核批准、打印 |
| 16 | M15 统计与报表 | 四张统计图、四张报表 |
| 17 | M16 工作台 | 待办首页 |
| 18 | M17 测试部署与交付 | staging 环境、交付文档 |

建议在四个点请用户看一次，及时纠正理解偏差：M05 之后（主数据与模板）、M09 之后（询价到报价）、M12 之后（全流程到定标）、M17 之后（交付）。

关键路径是 M05 → M09 → M10 → M11 → M12。真实 PPL 模板到位后按 [04-PPL模板规范](04-PPL模板规范.md) §9 替换定义，不改代码。

需要取舍时按此顺序裁剪（需用户同意）：M16 工作台 → 统计看板的部分筛选维度 → xlsx 在线预览（保留下载）→ 合同打印视图（保留数据）。
