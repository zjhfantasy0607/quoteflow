# M07 邀请、发布与邮件通知

> 覆盖：#3、#4 | 依赖：M04、M06

## 1. 目标

采购从供应商库按分类筛选并勾选受邀供应商，设置截止时间发布询价；系统自动给受邀供应商发邀请邮件（按收件人语言或中英对照）；支持补充邀请、催报（手动 + 截止前自动）、延期、发布后取消。同时建立轮次状态机的核心 `RoundStateService`。

## 2. 范围

**范围内**：受邀名单维护与候选查询；`RoundStateService`（统一的状态迁移入口：条件更新 + 同步 `Inquiry.currentRoundStatus/currentDeadline` + 审计）；第 1 轮发布（冻结 PPL 版本与变体、建报价单、发邀请）；补充邀请；手动催报；`autoReminder` 任务；延期；发布后取消（扩展 M06 的取消）；邮件模板 `invitation`、`reminder`、`change.deadline`、`change.cancel`；详情页"邀请供应商""供应商响应（仅状态）"页签。

**范围外**：截止任务、开标与密封视图（M10）；变更轮次发布（M13）。

## 3. 规则

| 编号 | 规则 |
|---|---|
| R07-1 | 候选供应商只含启用的；筛选：供应商分类多选（战略/优秀/普通，#3）、主营材料分类（默认询价单的材料类别，含下级，可清空）、关键字；已受邀的标记出来。 |
| R07-2 | 受邀名单可编辑的时机见 05 §3（第 1 轮发布前，或存在 DRAFT 变更轮次时）。 |
| R07-3 | 发布前置条件：询价单 `APPROVED`；受邀 ≥1 且全部启用（`INQUIRY_NO_INVITEES` / `INQUIRY_SUPPLIER_NOT_INVITABLE`）；截止 ≥ 现在 + `inquiry.minDeadlineHours`（`INQUIRY_DEADLINE_INVALID`）。 |
| R07-4 | 发布副作用（同一事务）：冻结当前激活模板集版本与询价单材料类别解析出的变体；每个受邀供应商一条 `Quote(INVITED, invitedAt = now)`；每家一封 `invitation` 邮件；轮次 → `WAITING_QUOTES`。"正式单 + 已邀请后触发"（#4）即由此实现。 |
| R07-5 | 邀请邮件发到供应商联系邮箱，抄送抄送邮箱；语言按供应商首选语言；内容：公司名称、正式询价号、标题、截止时间（标明 UTC+8）、询价行数、门户链接 `${APP_BASE_URL}/portal/quotes/<quoteId>`、采购联系人姓名和邮箱。**不含**项目号、其他供应商、任何金额。 |
| R07-6 | 发布对话框里提示"以下受邀供应商还没有可用的门户账号"（没有 ACTIVE 的供应商用户），可跳转开通，不阻止发布。 |
| R07-7 | 补充邀请：轮次 `WAITING_QUOTES` 时可以追加启用的供应商，写入名单、建报价单、发邀请。 |
| R07-8 | 手动催报：只能选未响应（`INVITED`）的报价单，每次点击每家发一封 `reminder`。 |
| R07-9 | 自动催报：`autoReminder` 任务每 10 分钟扫描 `WAITING_QUOTES` 且"现在 ≥ 截止 − `reminder.autoHoursBeforeDeadline` 小时"且 `autoReminderSentAt` 为空的轮次，给其中 `INVITED` 的报价单各发一封（`bizKey = REMINDER:AUTO:<roundId>:<supplierId>`），然后写 `autoReminderSentAt`。参数为 0 时不发。 |
| R07-10 | 延期按 05 §3；给受邀且未拒绝的供应商发 `change.deadline`。 |
| R07-11 | 发布后取消：报价单 → `VOID`，给受邀且未拒绝的供应商发 `change.cancel`（含取消原因）。 |
| R07-12 | `RoundStateService` 是唯一能改轮次状态的地方；每次迁移都按 05 §3 的表校验来源状态（条件更新），失败抛 `ROUND_INVALID_STATUS`。 |

## 4. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/inquiries/:id/invitees` | `inquiry:view` | 名单 + 是否有门户账号 |
| GET | `/api/inquiries/:id/invitee-candidates` | `inquiry:invite` | `categoryCodes`、`materialCategoryId`、`keyword`；分页 |
| PUT | `/api/inquiries/:id/invitees` | `inquiry:invite` | `{ supplierIds[] }` 整体替换 |
| POST | `/api/inquiries/:id/rounds/:roundNo/publish` | `inquiry:publish` | `{ deadline }` |
| POST | `/api/inquiries/:id/rounds/:roundNo/late-invite` | `inquiry:invite` | `{ supplierIds[] }` |
| POST | `/api/inquiries/:id/rounds/:roundNo/remind` | `inquiry:remind` | `{ quoteIds[] }` |
| PUT | `/api/inquiries/:id/rounds/:roundNo/deadline` | `inquiry:deadline` | `{ deadline }` |
| GET | `/api/inquiries/:id/rounds/:roundNo/responses` | `inquiry:view` | 本模块只返回状态字段（M10 补全密封逻辑） |

取消沿用 `POST /api/inquiries/:id/cancel`。

## 5. 前端

- 详情页"邀请供应商"页签：上方筛选（分类复选框、主营材料分类、搜索），下方候选表格（勾选、名称、编码、分类标签、主营分类、门户账号状态），右侧或顶部显示"已选择 N 家"，保存名单（参考 PPT #3）。发布后变为只读名单 +"补充邀请"按钮。
- 发布对话框：截止时间（日期时间选择，按 UTC+8，显示"北京时间"字样）、受邀名单确认、无门户账号的提示。
- "供应商响应"页签：表格（供应商、状态、邀请时间、首次查看、响应时间、版本数）+ 勾选未响应者"催报" + "延期"按钮。
- 邮件记录页能按询价单号筛到这些邮件。

## 6. 测试

- 候选筛选：按分类、按主营分类（含下级）、排除停用。
- 发布：前置条件逐条失败；成功后报价单数量、模板冻结值、`Inquiry.currentRoundStatus`、邮件数量和语言（zh-CN、en-US、bilingual 各一家）都正确；邮件正文不含项目号。
- 补充邀请、手动催报只针对 `INVITED`。
- 自动催报：TestClock 推进到截止前 23 小时 → 执行任务 → 只给未响应者发一次；再执行不重复；参数改为 0 不发。
- 延期：新截止早于原截止被拒；从 `QUOTES_CLOSED` 延期回到 `WAITING_QUOTES`（M10 有截止任务后补充此用例）。
- 发布后取消：报价单全部 `VOID`，取消邮件只发给未拒绝的。
