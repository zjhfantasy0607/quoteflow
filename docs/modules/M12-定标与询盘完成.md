# M12 定标与询盘完成

> 覆盖：#10、#11、#24 | 依赖：M11

## 1. 目标

采购主管指定 1 家中标，其余评标中的报价写入"未中标"；轮次到"评标完成"，询价单关闭只读（历史可查不可改）；在同一事务里生成合同草稿（带询价/报价快照）；通知中标与未中标供应商。

## 2. 范围

**范围内**：定标接口与对话框；报价终态；关闭进行中的议价；`completedAt`；`ContractDraftFactory`（创建 `Contract` 行与快照，合同管理界面在 M14）；积分 WON；邮件模板 `award`、`result`；全局只读检查；询价详情的完成横幅；门户的结果提示；`seed-demo.ts` 框架与场景 D5。

## 3. 规则

| 编号 | 规则 |
|---|---|
| R12-1 | 定标只能在轮次 `OPENED` 时进行，需要 `inquiry:award`；中标报价必须是 `EVALUATING`（`AWARD_INVALID_QUOTE`）。入围与否不限制（通常从入围中选）。 |
| R12-2 | 中标 → `WON`；其余 `EVALUATING` → `LOST`；`INVITED`（未响应）、`DECLINED` 不变。每轮恰好一条 `WON`（I-8）。 |
| R12-3 | 进行中的议价自动关闭（系统 CLOSE 消息，05 §5）。 |
| R12-4 | 轮次 → `EVALUATED`（`evaluatedAt`、`awardedById`、`awardComment`），`Inquiry.completedAt = now`，询盘完成（#11）。 |
| R12-5 | 同一事务内生成合同草稿：`contractNo`、`amount` = 中标版本 `totalAmount`、`currency`、`paymentTerms` 预填为中标版本 `payment_terms` 的字典名称、`snapshot` 按 02 §4 结构。 |
| R12-6 | 邮件：中标方收 `award`；`notify.sendResultToLosers = true` 时，`LOST` 的供应商收 `result`（礼貌告知未中标，不透露中标方和价格）；未响应、已拒绝的不发。 |
| R12-7 | 中标方积分 +`won`（`bizKey = WON:<roundId>:<supplierId>`）。 |
| R12-8 | 询价单完成或取消后，**所有修改类接口**（表头、行、附件、名单、轮次动作、入围、议价、定标）返回 `INQUIRY_COMPLETED_READONLY`；查询类接口照常（#11 历史可查不可改）。在 `InquiryAccessService.findEditableOrThrow()` 统一拦截。 |
| R12-9 | 定标记审计；同时并发两次定标只成功一次。 |

## 4. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/inquiries/:id/rounds/:roundNo/award` | `inquiry:award` | `{ quoteId, comment? }` → 最新询价详情（含合同 id） |

## 5. 前端

- 比价评标页签的"定标"按钮 → 对话框：评标中的供应商单选列表（名称、含税合计、是否入围）、定标说明，提示"其他供应商将被标记为未中标，定标后自动生成合同草稿"（参考 PPT #10）。
- 询价详情：完成后顶部横幅"评标已完成，中标供应商：XXX"，带"查看合同"链接；所有编辑按钮消失（参考 PPT #11）。
- 门户报价详情：`WON` 显示"恭喜中标"，`LOST` 显示"本次未中标，感谢参与"。

## 6. 测试

- 非 `OPENED` 定标被拒；中标对象非评标中被拒。
- 定标后：报价状态、轮次状态、`completedAt`、`Inquiry.currentRoundStatus` 正确；进行中的议价已关闭且有系统消息；合同草稿存在且快照字段齐全、金额等于中标版本合计。
- 邮件：中标 1 封；未中标按参数发或不发；未响应/拒绝的不发。
- 积分：中标方有 WON 条目，重复执行不重复。
- 只读：完成后调用改表头、加行、改名单、催报、延期、入围、议价、再次定标，全部返回 `INQUIRY_COMPLETED_READONLY`；查询接口正常。
- 并发定标只成功一次。

## 7. 验收

- [ ] 采购主管定标后，询价单显示"评标完成"且只读，合同列表出现草稿（M14 后可编辑）。
- [ ] 中标与未中标供应商分别收到对应邮件，门户显示结果。
