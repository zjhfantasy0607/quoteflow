# M11 比价矩阵与议价

> 覆盖：#7、#8、#30 | 依赖：M10

## 1. 目标

开标后出现比价矩阵（各家报价、变更备注、变更高亮、可导出）；评标中最多勾选 2 家入围，系统内填写目标价并通知；多轮议价（价格、规格、数量变更；拒绝须填原因、可附反提案），全程留痕直至双方成交。

## 2. 范围

**范围内**：比价矩阵接口与页面、Excel 导出；入围名单；议价（采购方接口 + 门户接口）、成交生成新报价版本；邮件模板 `negotiation.toSupplier`、`negotiation.toBuyer`、`negotiation.agreed`；字段权限 `negotiation.amount`；把矩阵与导出加入密封测试集；演示场景 D4。

## 3. 规则

| 编号 | 规则 |
|---|---|
| R11-1 | 矩阵只在轮次 `OPENED` / `EVALUATED`（或曾开标后被作废）时可用，需要 `inquiry:evaluate`；否则 `QUOTE_SEALED`。 |
| R11-2 | 汇总表：每家供应商一行——状态（评标中/已拒绝/未响应/已中标/未中标）、含税合计、最长交期、版本数、最后提交时间、变更备注、是否入围；拒绝的显示原因。含税合计最低的高亮。 |
| R11-3 | 明细：按询价行切换，行为 `inMatrix` 列，列为各家供应商的当前版本取值；每个询价行的含税单价最低者高亮。 |
| R11-4 | 变更高亮：当前版本与该报价单上一版本逐行逐列比较，变化的单元格高亮，悬停显示原值；议价成交生成的版本同样参与比较。 |
| R11-5 | 导出 Excel：汇总 sheet + 每个询价行一个明细 sheet（或一个长表），遵守 `quote.amount` 脱敏（被脱敏的写"***"）。需要 `inquiry:export`。 |
| R11-6 | 入围：每轮最多 2 家（`SHORTLIST_LIMIT_EXCEEDED`），只能选 `EVALUATING` 的报价单（`SHORTLIST_INVALID_QUOTE`）；已经发过议价消息的不能移出（`SHORTLIST_LOCKED`）。 |
| R11-7 | 议价轮流规则、消息类型、必填项、成交生成版本，全部按 05 §5。 |
| R11-8 | 价格 ≥ 0、最多 4 位小数；数量 > 0、最多 4 位小数；`specNote` ≤ 500 字；每条消息附件最多 10 个。 |
| R11-9 | 成交（任一方 ACCEPT）后，比价矩阵立即显示新版本并对变化高亮；采购方可再发起 OFFER 继续议价。 |
| R11-10 | 议价相关的金额对内部用户按 `negotiation.amount` 脱敏；供应商始终看到自己议价里的全部内容。 |
| R11-11 | 议价每一步都记审计并出现在双方的议价时间线里（#30 全程留痕）。 |

## 4. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/inquiries/:id/rounds/:roundNo/matrix` | `inquiry:evaluate` | 汇总 + 明细 + 变更信息 |
| GET | `/api/inquiries/:id/rounds/:roundNo/matrix/export` | `inquiry:export` | xlsx |
| PUT | `/api/inquiries/:id/rounds/:roundNo/shortlist` | `inquiry:evaluate` | `{ quoteIds[] }`（≤2） |
| GET | `/api/quotes/:quoteId/negotiation` | `inquiry:evaluate` | 议价线程（按数据权限） |
| POST | `/api/quotes/:quoteId/negotiation/offer` | `inquiry:evaluate` | `{ lines[], content?, attachmentFileIds? }` |
| POST | `/api/quotes/:quoteId/negotiation/accept` | `inquiry:evaluate` | `{ messageId }`（接受供应商的 COUNTER） |
| POST | `/api/quotes/:quoteId/negotiation/close` | `inquiry:evaluate` | `{ content? }` |
| GET | `/api/portal/quotes/:quoteId/negotiation` | SupplierOnly | |
| POST | `/api/portal/quotes/:quoteId/negotiation/respond` | SupplierOnly | `{ type: 'ACCEPT' \| 'REJECT' \| 'COUNTER', replyToId, lines?, content?, attachmentFileIds? }` |

## 5. 前端

- 询价详情"比价评标"页签：汇总表（入围勾选框，最多 2 个；导出按钮；"定标"按钮在 M12 加）→ 询价行切换器 → 明细矩阵（高亮最低价、变更单元格；"只看差异"开关），参考 PPT #7、#8。
- "议价"页签（有入围供应商时出现）：每家入围供应商一个子页签，时间线展示每条消息（轮次标签、方向、目标价/反提案表格、说明、附件、时间、状态），参考 PPT #30；底部"发起下一轮议价"表单：逐行填目标含税单价 / 数量 / 规格说明，方案说明，附件。轮到供应商时表单禁用并显示"等待供应商回复"。
- 门户报价详情增加"议价"区：同样的时间线；轮到供应商时显示"接受 / 拒绝 / 反提案"三个操作（拒绝、反提案必须填原因）。

## 6. 测试

- 矩阵：开标前 `QUOTE_SEALED`（加入密封测试集）；最低价高亮标记正确；上一版本对比得到的变更单元格正确；拒绝与未响应的供应商出现在汇总表里。
- 导出：去掉 `quote.amount` 后导出文件里金额为"***"（加入密封测试集：开标前导出被拒）。
- 入围：第 3 家被拒；非评标中被拒；发过议价的移出被拒。
- 议价：未入围不能发 OFFER；轮次规则（连续两次 OFFER 被拒、供应商在采购方回合回复被拒）；REJECT 无原因被拒；COUNTER 空行被拒；供应商 ACCEPT → 新版本（来源 NEGOTIATION、价格和数量覆盖正确、公式重算、合计正确）、`Negotiation` 为 `AGREED`、当前版本切换；采购方 ACCEPT 供应商的 COUNTER 同理；AGREED 后再 OFFER 回到 OPEN；CLOSE 后任何操作被拒。
- 邮件：每一步给对方发一封，语言正确。
- 字段权限：没有 `negotiation.amount` 的内部用户看到的议价价格为 null。

## 7. 验收
