## 1. 目标

全量回归与安全检查、浏览器端主流程自动化测试、可部署的镜像与测试/演示环境、交付文档。

## 2. 范围

### 2.1 测试与检查

1. **Playwright 主流程**（`apps/web/e2e/`，跑在本机 dev 环境上）：PD 建单传规格 → 采购主管审批 → 采购员邀请发布 → 供应商 A 在线报价、供应商 B 用 Excel 报价、供应商 C 拒绝 → 截止（用接口推进或设置很近的截止时间）→ 开标 → 比价 → 入围议价 → 成交 → 定标 → 合同审核、批准。中英文各跑一次关键页面截图。
2. **权限矩阵测试**：对每个预置角色，抽取每个模块的代表性接口，断言有权限 200/201、无权限 403；断言供应商访问任何内部接口 403。
3. **安全复查清单**：密封测试集覆盖所有报价数据出口（M10/M11/M13/M15 补充项齐全）；隔离测试集；CSRF；登录限流；会话失效；上传魔数；`Content-Disposition` 注入（文件名含引号、换行）；响应 DTO 不含 `passwordHash`、`tokenHash`、`draftValues`（对内部接口）。
4. **双语复查**：`check:i18n` 通过；英文界面逐页走查，无中文残留、无截断；邮件三种语言各发一封核对。
5. **性能抽查**：用脚本造 1000 张询价单、5000 条报价单，列表接口 < 1 秒，统计接口 < 3 秒。

### 2.2 部署

1. `docker/api.Dockerfile`：`node:24-alpine` 多阶段——安装依赖、构建 shared 与 api、`prisma generate`；运行阶段只带生产依赖与产物；启动命令先 `prisma migrate deploy` 再 `node dist/main.js`；健康检查调用 `/api/health`。根目录 `.dockerignore`（两个镜像共用）排除 `node_modules`、`dist`、`apps/api/storage`、`.env`：开发机是 Windows，本机 `node_modules` 里的原生二进制（Prisma 引擎、esbuild、rollup）都是 Windows 版，依赖必须在镜像里 `npm ci`。
2. `docker/web.Dockerfile`：构建前端，`nginx:alpine` 托管；`docker/nginx.conf`：静态资源缓存、SPA 回退到 `index.html`、`/api` 反代到 api、上传大小 60MB。
3. `docker/compose.staging.yml`：项目名 `quoteflow-staging`，服务 postgres（命名卷）、mailpit、api（命名卷存上传文件）、web；api、web 用 build 构建镜像，不 bind mount 源码目录；环境变量与生产项分离（`EXCEL_SIGNING_SECRET` 等必须设置）。
4. 本机访问 staging：web 端口发布到 `127.0.0.1:18080`。给客户演示需请用户另行配置对外访问入口。
5. 备份脚本 `scripts/backup.sh`：`docker exec` 执行 `pg_dump` 输出到本机，`docker cp` 导出上传目录。
6. 生产部署说明（部署地点确定后执行）：同一套镜像、反向代理 TLS、`COOKIE_SECURE=true`、真实 SMTP 与发信域名（SPF/DKIM）、每日备份、国内云需 ICP 备案。
