# M01 认证、用户与角色权限

> 覆盖：#19、#27（系统账户、角色管理）、#18（账号级语言） | 依赖：M00

## 1. 目标

登录会话、全局守卫、功能/数据/字段三类权限、内部用户管理、角色权限配置、操作日志写入。做完后所有后续接口都能用装饰器声明权限，用 `ScopeService` / `FieldMaskService` 做数据权限和脱敏。

## 2. 范围

**范围内**：登录、登出、当前用户、修改密码、账号语言；CsrfGuard / SessionAuthGuard / UserTypeGuard / PermissionsGuard 与装饰器（03 §5）；`ScopeService`、`FieldMaskService`（框架与 `supplier.contact`，其余字段码由对应模块接入）；`AuditService.log()`（写入，查看页在 M02）；内部用户 CRUD；角色 CRUD 与权限树；shared 的 `permissions.ts`、`field-permissions.ts`、`roles.ts`；前端登录页、路由守卫、`v-perm`、菜单按权限过滤、用户管理页、角色权限页、修改密码对话框；seed：角色、内部用户、`department` 字典。

**范围外**：找回/重置密码（需要邮件，M02）；供应商账号与激活（M04）。

## 3. 规则

| 编号 | 规则 |
|---|---|
| R01-1 | 内部用户用用户名登录，供应商用邮箱登录（都存在 `username`）。用户不存在和密码错误统一返回 `AUTH_INVALID_CREDENTIALS`。 |
| R01-2 | `DISABLED` 用户、所属供应商已停用的供应商用户返回 `AUTH_ACCOUNT_DISABLED`；`PENDING_ACTIVATION` 返回 `AUTH_ACCOUNT_NOT_ACTIVATED`。 |
| R01-3 | 会话按 01 §6：httpOnly cookie、只存哈希、滑动续期；过期或被删除后返回 401。 |
| R01-4 | 非 GET 请求缺少 `X-Requested-With: XMLHttpRequest` 返回 403 `CSRF_REJECTED`（`@Public` 接口也校验）。 |
| R01-5 | 权限每个请求实时从数据库加载：修改角色权限或用户角色后，该用户**下一个请求**即生效，无需重新登录（#19 立即生效）。 |
| R01-6 | 停用用户、管理员重置密码 → 删除该用户全部会话；用户修改自己的密码 → 保留当前会话、删除其他会话。 |
| R01-7 | 预置角色不可删除、code 不可改；`SUPPLIER` 角色的权限不可改；提交不存在的权限码或字段码返回 `ROLE_UNKNOWN_PERMISSION`。 |
| R01-8 | 仍有用户的角色不可删除（`ROLE_IN_USE`）。 |
| R01-9 | 内部用户至少有一个非供应商角色；用户名唯一；邮箱可空但唯一；不能停用自己。 |
| R01-10 | 数据范围取用户所有角色中最宽的；`ScopeService.inquiryWhere(user)` 按 05 §11 生成条件。 |
| R01-11 | `FieldMaskService` 被脱敏字段置 null 并在对象上加 `maskedFields`。 |
| R01-12 | 密码至少 8 位且同时含字母和数字（`AUTH_PASSWORD_WEAK`）；修改密码要校验原密码（`AUTH_OLD_PASSWORD_WRONG`）。 |
| R01-13 | `PUT /api/auth/me/locale` 保存账号语言；登录后前端按账号语言显示；未登录页面用 localStorage 里的语言。 |
| R01-14 | 审计：登录成功/失败（失败只记用户名和 IP）、登出、用户新建/编辑/停用/重置密码、角色新建/编辑/删除（记录权限差异）。 |
| R01-15 | 登录接口同一 IP 每分钟最多 10 次，超出返回 `RATE_LIMITED`。 |

## 4. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/auth/login` | Public | `{ username, password }` → 设 cookie，返回 `MeDto` |
| POST | `/api/auth/logout` | AnyUser | 删除当前会话 |
| GET | `/api/auth/me` | AnyUser | `MeDto`：user（含 supplier 简要）、roles、permissions、fieldPermissions、dataScope |
| PUT | `/api/auth/me/locale` | AnyUser | `{ locale: 'zh-CN' \| 'en-US' }` |
| PUT | `/api/auth/me/password` | AnyUser | `{ oldPassword, newPassword }` |
| GET | `/api/system/users` | `system:user:view` | 筛选：keyword、status、roleId；只列内部用户 |
| GET | `/api/system/users/:id` | `system:user:view` | |
| POST | `/api/system/users` | `system:user:manage` | `{ username, name, email?, phone?, departmentCode?, roleIds[], password, locale? }` |
| PUT | `/api/system/users/:id` | `system:user:manage` | 不能改 username |
| PUT | `/api/system/users/:id/status` | `system:user:manage` | `{ status: 'ACTIVE' \| 'DISABLED' }` |
| POST | `/api/system/users/:id/reset-password` | `system:user:manage` | `{ newPassword }` |
| GET | `/api/system/roles` | `system:role:view` | 含每个角色的用户数 |
| GET | `/api/system/roles/:id` | `system:role:view` | |
| POST | `/api/system/roles` | `system:role:manage` | `{ code, nameZh, nameEn, description?, dataScope, permissions[], fieldPermissions[] }` |
| PUT | `/api/system/roles/:id` | `system:role:manage` | |
| DELETE | `/api/system/roles/:id` | `system:role:manage` | |
| GET | `/api/system/permissions` | `system:role:view` | 权限树 + 敏感字段清单（来自 shared，供角色页渲染） |

## 5. 前端

- `/login`：用户名、密码、语言切换；登录后按用户类型跳 `/workbench` 或 `/portal`，有 `redirect` 参数时跳回原页面。
- `authStore`：`me`、`hasPerm(code)`、`hasField(code)`、`setLocale()`（同时改 i18n、Element Plus、dayjs，并调用接口保存）、`logout()`。
- 路由守卫与菜单过滤（01 §5.2）；`v-perm` 指令。
- 顶栏用户菜单：修改密码（对话框）、退出登录。
- `/system/users`：列表（用户名、姓名、部门、角色、状态、最后登录）+ 新建/编辑对话框 + 停用/启用 + 重置密码。
- `/system/roles`：左侧角色列表，右侧角色详情，三个页签"功能权限 / 数据权限 / 字段权限"（参考 PPT #19：模块树 + 勾选；数据权限单选 SELF/DEPT/ALL；字段权限勾选敏感字段）。预置角色显示标识，code 只读。

## 6. 种子数据

06 §2.1 角色、§2.2 内部用户、§2.3 中的 `department` 字典。

## 7. 测试

- 登录成功/失败/停用/未激活/限流；登出后 401；会话过期（TestClock 前进 13 小时）后 401。
- CSRF：缺头的 POST 返回 403。
- **R01-5**：BUYER 访问 `/api/system/users` 得 403 → 管理员给 BUYER 角色加 `system:user:view` → 同一会话下一次请求得 200。
- 预置角色删除被拒；未知权限码被拒；有用户的角色删除被拒。
- 停用用户后其会话立即失效。
- `ScopeService`：SELF / DEPT / ALL 三种用户对同一批询价单的可见性（M06 有询价单后补充，本模块先对 where 条件做单元测试）。
- web：`v-perm` 无权限时不渲染；菜单按权限过滤。

## 8. 验收

- [ ] 六个预置账号都能登录，菜单与 05 §12 的权限对应。
- [ ] 改角色权限后，已登录用户刷新页面菜单立即变化。
- [ ] 切换语言后退出再登录，界面仍是上次的语言。
- [ ] 角色页可以新建自定义角色并分配三类权限。
