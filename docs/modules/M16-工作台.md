# M16 工作台（待办）

> 覆盖：体验增强，不对应单独需求（可裁剪） | 依赖：M12（合同待办依赖 M14）

## 1. 目标

登录后的首页集中显示"现在该我处理的事"，减少在列表里找单据。只做邮件之外的系统内提醒，不做站内信。

## 2. 范围与规则

**采购方 `/workbench`**：按当前用户的权限与数据权限显示卡片（数字 + 前 5 条列表 + "查看全部"链接）：

| 卡片 | 条件 | 所需权限 |
|---|---|---|
| 待我审批 | 询价单 `PENDING_APPROVAL` | `inquiry:approve` |
| 我的草稿 / 被驳回 | `DRAFT` 且负责人/创建人/PD 是本人（被驳回的带标识） | `inquiry:create` |
| 待发布 | `APPROVED` 且当前轮 `DRAFT` | `inquiry:publish` |
| 等待报价 | 当前轮 `WAITING_QUOTES`，按截止时间升序，显示响应进度"已响应 2/3" | `inquiry:view` |
| 待开标 | 当前轮 `QUOTES_CLOSED` | `inquiry:open` |
| 议价待处理 | 进行中议价，最后一条消息来自供应商 | `inquiry:evaluate` |
| 待审核合同 / 待批准合同 | 合同 `PENDING_REVIEW` / `PENDING_APPROVAL` | `contract:review` / `contract:approve` |

**供应商 `/portal`**：待报价（`WAITING_QUOTES` 且自己未拒绝，按截止升序，显示"已提交 / 未提交"）、议价待回复（最后一条是采购方 OFFER）、最近结果（`WON` / `LOST`，最近 30 天）。

- R16-1 卡片内容遵守数据权限、密封（不显示金额）、供应商隔离。
- R16-2 一个接口一次返回全部卡片：`GET /api/workbench`、`GET /api/portal/workbench`。

## 3. 测试

- 不同角色看到的卡片集合正确；数据权限过滤正确；供应商只看到自己的。

## 4. 实施步骤

api 两个聚合接口 → e2e → 前端两个首页 → verify，更新进度。
