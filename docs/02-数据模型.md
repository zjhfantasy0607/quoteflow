# 02 数据模型

完整定义见 [schema.prisma](schema.prisma)：32 个模型、17 个枚举，已用 Prisma 6.19.3 校验，并在 PostgreSQL 15 上 `db push` 建表验证。

**来源规则**：M00 把它复制到 `apps/api/prisma/schema.prisma` 并生成第一个迁移，之后以代码里的那份为准，`docs/schema.prisma` 只作设计基线、不再同步。改动 schema 时，在本文 §8 变更记录里写一行（日期、模块、改了什么、为什么）。

| 分组 | 模型 | 说明 |
|---|---|---|
| 账号权限 | `User`、`Role`、`UserRole`、`Session`、`UserToken` | 内部用户与供应商用户共用 `User`，以 `userType` 区分 |
| 系统设置 | `DictType`、`DictItem`、`SystemParam`、`Sequence`、`AuditLog` | |

| 主数据 | `MaterialCategory`、`Material`、`Supplier`、`SupplierMaterialCategory`、`SupplierPointsEntry`、`PplTemplateSet` | |
| 询价 | `Inquiry`、`InquiryApproval`、`InquiryInvitee`、`InquiryRound`、`InquiryLine`、`InquiryFile` | |
| 报价议价 | `Quote`、`QuoteVersion`、`Negotiation`、`NegotiationMessage` | |
| 合同 | `Contract`、`ContractApproval` | |
| 邮件 | `EmailMessage` | 发件箱 + 发送记录 |

## 2. 核心关系

```
Inquiry 1─* InquiryRound 1─* InquiryLine 1─* InquiryFile(lineId 非空)
   │            │  └────────────────────* InquiryFile(lineId 为空 = 整单附件)
   │            └─* Quote（每轮每家供应商一条）1─* QuoteVersion
   │                   │  currentVersionId ─→ QuoteVersion（最新有效版本）
   │                   └─1 Negotiation 1─* NegotiationMessage ─(成交)→ QuoteVersion(source=NEGOTIATION)
   ├─* InquiryInvitee *─1 Supplier          （本单受邀名单，发布时据此生成 Quote）
   ├─* InquiryApproval                      （提交/通过/驳回记录）
   └─1 Contract ─→ Quote、QuoteVersion（中标版本）、Supplier；1─* ContractApproval

MaterialCategory（树）1─* Material；*─* Supplier（主营分类）；1─* InquiryLine
User *─* Role；Supplier 1─* User（门户账号）
```

**为什么要有轮次（InquiryRound）**：#12 规格变更要求"同一询价号新轮次、历史轮次只读"。每轮有自己的询价行副本、附件、截止时间、状态和报价，旧轮次整体冻结，规格对比按 `InquiryLine.sourceLineId` 对上一轮的行做匹配。

**两层状态**：`Inquiry.docStatus` 管单据审批（#22），`InquiryRound.status` 管询比价资源状态（#23）。列表需要按"当前轮次状态"筛选，所以在 `Inquiry` 上冗余了 `currentRoundStatus`、`currentDeadline`。显示状态由两者组合得出，见 05 §2。

## 3. 不变量（实现和测试都要保证）

| 编号 | 不变量 |
|---|---|
| I-1 | 创建询价单时同时创建 `roundNo = 1` 的轮次（DRAFT）。 |
| I-2 | `Inquiry.currentRoundStatus / currentDeadline` 永远等于第 `currentRoundNo` 轮的 `status / deadline`。**只有 `RoundStateService` 能修改轮次状态**，并在同一事务里同步这两个冗余字段。 |
| I-3 | 同一询价单最多一个 DRAFT 轮次；`roundNo` 从 1 连续递增；`currentRoundNo` 只在新轮次发布时才切换。 |
| I-4 | 轮次发布后，其询价行、附件、`pplTemplateVersion`、`pplVariantCode` 不可再修改。第 1 轮的行和附件在询价单提交审批后就冻结（审批通过的内容不能再被改）。 |
| I-5 | `Quote` 只在轮次发布或补充邀请时创建，`(roundId, supplierId)` 唯一。 |
| I-6 | `Quote.currentVersionId` 必须指向本报价单自己的版本；`versionNo` 从 1 连续递增；版本创建后不可修改。 |
| I-7 | 每轮 `shortlisted = true` 的报价最多 2 条（#8）。 |
| I-8 | 每轮最多一条 `WON`；`EVALUATED` 的轮次恰好有一条 `WON`。 |
| I-9 | `Contract` 与 `Inquiry` 一对一，只在定标事务里创建。 |
| I-10 | `EmailMessage` 与触发它的业务变更在同一事务里写入。 |
| I-11 | `AuditLog.summary/detail`、`EmailMessage` 发给内部用户的正文里不出现开标前的报价金额。 |

## 4. JSON 字段结构

类型定义放在 `packages/shared/src/types/`，写入前用 zod 校验。

**`PplValue`**：`string | number | boolean | string[] | null`。decimal / money / percent 用字符串（`"0.0850"`），int 用 number，bool 用 boolean，date 用 `"YYYY-MM-DD"`，multiEnum 用字典编码数组。空值不写或写 null。

**`Quote.draftValues`**（供应商草稿，采购方任何时候都看不到）：

```ts
{
  lines: Record<string /* lineId */, Record<string /* 列 key */, PplValue>>; // 只含供应商填写列
  remark?: string;
  changeNote?: string;
  attachmentFileIds?: string[];  // 提交时转成 Attachment(ownerType=QUOTE_VERSION)
  source?: 'ONLINE' | 'EXCEL';   // 最近一次写入草稿的方式，提交时决定 QuoteVersion.source
}
```

**`QuoteVersion.values`**：

```ts
{
  lines: Array<{
    lineId: string;
    lineNo: number;
    values: Record<string, PplValue>; // 供应商填写列 + 公式列（公式列由服务端计算写入，忽略客户端传值）
  }>;
}
```

预填列（行号、物料名称、规格、数量、币种等）**不存**在报价里，展示时从询价行取。轮次发布后询价行不可改（I-4），所以这样做是安全的。

**`NegotiationMessage.lines`**：

```ts
Array<{ lineId: string; unitPriceInclTax?: string; quantity?: string; specNote?: string }>
```

**`Contract.snapshot`**（定标时冻结，之后模板、主数据怎么改都不影响合同展示）：

```ts
{
  capturedAt: string;
  inquiry: { id, formalNo, projectNo, title, currency, roundNo,
             materialCategory: { code, nameZh, nameEn }, owner: { id, name } };
  lines: Array<{ lineId, lineNo, materialCode, nameZh, nameEn, spec,
                 unit: { code, nameZh, nameEn }, quantity, category: { code, nameZh, nameEn } }>;
  supplier: { id, code, nameZh, nameEn, contactName, contactEmail, contactPhone };
  quoteVersion: { id, versionNo, source, submittedAt, totalAmount, currency,
                  values, remark, changeNote };
  columns: PplResolvedColumn[];      // 该轮冻结的列定义，用于渲染字段标签
  negotiation: Array<{ seq, party, type, lines, content, createdAt }> | null;
  files: Array<{ fileId, originalName, kind, lineNo: number | null }>;
}
```

**`SystemParam.value`**：每个 key 的结构和默认值定义在 `packages/shared/src/params.ts`，见 05 §8。

**`PplTemplateSet.definition`**：结构见 [04-PPL模板规范](04-PPL模板规范.md) §3。

## 6. 删除策略

- 主数据（材料、供应商、字典项、用户）**不物理删除**，用 `status = DISABLED` 停用。停用的主数据不能被新单据选用，历史单据照常显示。
- 材料分类只有在没有下级、没有材料、没有询价行、没有供应商引用时才能删除，否则只能停用。
- 自定义角色在没有用户时可删除；预置角色不可删除。
- 询价单不删除，只能取消（`CANCELLED`）。DRAFT 轮次里的询价行和附件可以物理删除。
- `FileObject` 只由清理任务删除（未被引用超过 24 小时）。

## 7. 索引与查询提示

- 询价列表：`Inquiry(docStatus, currentRoundStatus)`、`ownerId`、`projectNo` 已建索引；关键字搜索对 `draftNo / formalNo / title / projectNo` 做 `contains`（`mode: 'insensitive'`），数据量小，不建全文索引。
- 截止任务：`InquiryRound(status, deadline)`。
- 门户列表：`Quote(supplierId, status)`。
- 统计以 JS 聚合为主（年数据量在千级），避免手写 SQL；确需原生 SQL 时注意 Prisma 默认的表名和列名是大小写敏感的（`"InquiryRound"."publishedAt"`）。
