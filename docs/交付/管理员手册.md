# 管理员手册

面向系统管理员（预置角色"系统管理员"，演示账号 `admin`）。所有设置在左侧菜单"系统设置"里，保存后立即生效（已登录的用户下一次操作就按新设置执行，不需要重新登录）。所有修改都记在"操作日志"里。

## 1. 用户

系统设置 › 用户管理。

- **新建内部用户**：用户名（登录用，不区分大小写）、姓名、邮箱（接收审批、议价、合同等邮件）、部门（数据权限"本部门"按它判断）、角色（可多选，权限取并集、数据范围取最宽）、界面语言、初始密码（至少 8 位，包含字母和数字）。初始密码请通过安全渠道告诉本人，登录后在右上角"修改密码"改掉。
- **重置密码**：管理员输入新密码，该用户已登录的会话全部失效。
- **停用**：停用后不能登录，已有会话立即失效；历史单据里的姓名保留。不能删除用户。
- **供应商的门户账号**不在这里管理：在"供应商管理 › 供应商详情 › 门户账号"开通、重发激活邮件、启用 / 停用（需要"供应商门户账号"权限，通常是采购员）。供应商被停用时其门户账号自动不能登录。

## 2. 角色与权限

系统设置 › 角色权限。每个角色有三类权限：

| 类别 | 说明 |
|---|---|
| 功能权限 | 46 个权限码，按模块分组勾选（如"询价 › 审批""合同 › 批准"）。菜单、按钮和接口都按它控制 |
| 数据范围 | 本人（负责人、PD、创建人是自己的单据）、本部门（单据创建人的部门与自己相同）、全部。用于询价单及其报价、议价、合同、报表 |
| 敏感字段 | 报价金额、议价金额、合同金额、供应商联系方式。没有的显示 🔒 |

预置角色（系统管理员、产品开发、采购员、采购主管、合同批准人、供应商）不能删除、不能改编码，但可以调整权限（供应商角色除外）。默认权限见 [05-状态机与权限](../05-状态机与权限.md) §12。需要新的岗位时新建自定义角色，再分配给用户。有用户的角色不能删除。

## 3. 数据字典

系统设置 › 数据字典。维护下拉选项的中英文名称、排序和启用状态：币种、单位、拒绝报价原因、付款方式等。系统内置的字典类型和其中的选项都不能删除，只能停用（停用后新单据不能再选，历史单据照常显示）；自建的字典类型可以删除。

## 4. 系统参数

系统设置 › 系统参数。

| 参数 | 说明 |
|---|---|
| 公司资料 | 公司中英文名称、地址、电话：邮件抬头、供应商门户顶栏、合同打印版的甲方。**上线前必须填写** |
| 开标前可查看报价的角色 | 默认为空，即开标前任何人（包括管理员）都看不到报价金额和内容，只能看到提交状态和时间。加入某个角色后，该角色可以在开标前查看报价（需求 #23 补充，待确认事项 A-02）。请谨慎设置 |
| 发布 / 延期的最短截止小时数 | 截止时间至少比当前晚几小时，默认 1 |
| 自动催报 | 截止前几小时给还没响应的供应商发一次催报，默认 24，0 表示关闭 |
| 是否通知未中标供应商 | 定标后是否给未中标的供应商发结果邮件，默认是 |
| 积分规则 | 准时报价、快速响应（及其小时数）、中标、未响应的加减分（待确认事项 A-10）。只影响之后发生的事件，已记的积分不重算；个别调整用"统计分析 › 数据报表 › 积分记录 › 手工调整" |
| 上传限制 | 规格书、产品图、附件的大小上限，每行产品图张数 |
| 会话有效期 | 小时数，有操作时自动续期 |

## 5. PPL 模板

系统设置 › PPL 模板。PPL 是供应商报价的统一格式（需求 #6）：每列的中英文标签、类型、是否必填、是否敏感金额、是否进比价矩阵、是否属于物流信息，以及按材料分类使用的变体。

- 当前激活的是占位版本 v0（70 列）。拿到客户的正式 PPL 后按 [04-PPL模板规范](../04-PPL模板规范.md) §9 替换：整理成定义文件 → 在本页上传（系统先校验，校验通过生成新版本，不会自动激活）→ 核对列表 → 激活。
- **激活只影响之后发布的轮次**。已经发布的轮次冻结了当时的版本，报价、比价、导出照旧使用旧版本，不会被打乱。
- 材料分类绑定哪个变体在"材料管理 › 材料分类"里设置（子分类可以继承上级）。

## 6. 邮件

系统设置 › 邮件记录。每封邮件（邀请、催报、延期、开标、议价、中标 / 未中标、规格变更、取消、审批、合同审批、账号激活、找回密码）都有记录：收件人、主题、语言、状态（待发送 / 已发送 / 失败）、失败原因、重试次数，可以查看正文和重发。

排障：

1. **状态一直是"待发送"**：发件任务每 30 秒处理一次。检查 api 是否在运行（`docker compose ... ps`），日志里是否有错误（`docker compose ... logs api`）。
2. **状态是"失败"**：看失败原因。常见的有 SMTP 地址或端口错误、账号密码错误、发件地址未被邮件服务允许（`MAIL_FROM` 要与 SMTP 账号匹配）。改好配置（[部署手册](部署手册.md) §3）重启 api 后，在本页"重发"。
3. **显示已发送但对方没收到**：多数是进了垃圾箱或被拦截。正式环境要给发信域名配置 SPF / DKIM（部署手册 §8），并让对方把发件地址加白名单。
4. **供应商说没收到邀请**：先在本页按供应商邮箱搜索；也可以在询价单"供应商响应"里对未响应的供应商"催报"。供应商的联系邮箱、抄送邮箱在供应商详情里维护。

staging 环境的邮件都进 Mailpit（`http://127.0.0.1:18026`），不会真正发出。

## 7. 操作日志

系统设置 › 操作日志。登录（成功和失败）、主数据修改、单据流转、权限与参数修改等都有记录：时间、操作人、IP、动作、对象与摘要。日志里不记录报价金额和报价内容（开标前密封）。

## 8. 日常维护

- **备份**：每天自动执行 `scripts/backup.sh`（部署手册 §6），定期确认备份文件在增加、能恢复。
- **账号**：员工离职时停用账号；岗位变化时调整角色。
- **主数据**：材料分类、供应商分类由采购主管维护；材料库、供应商由采购员维护。
- **升级**：按部署手册 §5，升级前先备份。
