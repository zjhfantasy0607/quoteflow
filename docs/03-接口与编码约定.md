# 03 接口与编码约定

所有模块共同遵守。和本文冲突的写法一律按本文改。

## 1. REST 约定

- 前缀 `/api`。资源名用复数 kebab-case：`/api/inquiries`、`/api/material-categories`。JSON 字段用 camelCase。
- ID 是 cuid 字符串，路径参数不做数字转换。
- 查询 `GET`；新建 `POST`（返回 201）；整体更新 `PUT`；删除 `DELETE`；**状态动作用 `POST` 子路径**：`POST /api/inquiries/:id/submit`、`.../approve`、`.../rounds/:roundNo/open`，动作接口加 `@HttpCode(200)`。
- 用户名、邮箱统一转小写后存储和比较（登录不区分大小写）。
- 分页参数 `page`（从 1 开始）、`pageSize`（默认 20，最大 100）；列表响应统一为 `{ items, total, page, pageSize }`。
- 排序参数 `sort=createdAt:desc`（只允许各接口白名单内的字段）。
- 时间参数和返回值都是 ISO 8601 字符串（UTC）。日期区间用 `from`、`to`（含当天，按 UTC+8 解释）。
- 布尔查询参数写 `true/false`，schema 里用 `z.enum(['true','false']).transform(...)` 或 `z.coerce.boolean()` 之外的明确写法（`z.coerce.boolean()` 会把 `"false"` 当成 true，禁止使用）。
- 文件导出接口直接返回文件流（`Content-Disposition: attachment; filename*=UTF-8''...`）。

## 2. 成功响应

- 直接返回数据对象，不包 `{ code, data }` 外壳。新建返回 201 + 新对象；动作接口返回 200 + 动作后的最新详情（前端用它刷新页面）。
- 详情类响应（询价单、轮次、门户报价单、合同）带 `allowedActions: string[]`，见 §6。
- 被脱敏的字段值为 `null`，同时在该对象上返回 `maskedFields: string[]`。

## 3. 错误响应

```json
{
  "code": "QUOTE_DEADLINE_PASSED",
  "message": "Quote deadline has passed",
  "params": { "deadline": "2026-11-20T09:00:00.000Z" },
  "details": []
}
```

- `code` 是前端翻译用的唯一依据（`t('errors.' + code, params)`）；`message` 是给开发者看的英文，前端不直接展示（找不到翻译时才兜底显示）。
- `details` 按错误类型约定结构：

| 错误 | details 结构 |
|---|---|
| `VALIDATION_FAILED` | `[{ path: 'lines.0.quantity', code: 'too_small', message }]` |
| `EXCEL_HEADER_MISMATCH` | `{ expected: string[], actual: string[], missing: string[], extra: string[], orderMismatch: boolean }` |
| `EXCEL_ROWS_INVALID` | `[{ row: 5, column: '规格型号 / Specification', code: 'required', message }]` |
| `QUOTE_VALUES_INVALID` | `[{ lineId, lineNo, key, code, params?, message }]` |
| `PPL_DEFINITION_INVALID` | `[{ path, message }]` |

`EXCEL_ROWS_INVALID` 的 `details[].code`（前端在 `excel.rowErrors.<code>` 翻译，`params` 作为插值）：通用的 `required`、`too_long`（max）、`invalid_email`、`invalid_integer`、`invalid_number`、`too_many_decimals`（max）、`too_small`（min）由 `ExcelTemplateService` 产生；业务校验另有 `invalid_code`、`duplicate_code`（row：与第几行重复）、`unit_not_found`、`unit_disabled`、`category_not_found`、`category_disabled`、`invalid_status`（M03 起，供应商、询价行导入复用）；供应商导入另有 `invalid_credit_code`、`duplicate_credit_code`（row）、`credit_code_taken`（code：占用它的供应商编码）、`supplier_category_not_found`、`supplier_category_disabled`、`main_category_not_found`（code）、`main_category_disabled`（code）、`invalid_language`（M04）；询价行导入另有 `not_positive`（数量必须大于 0）、`too_large`（max：数量超过 Decimal(18,4) 能存的最大值），物料编码匹配到的材料所属分类已停用时在物料编码列报 `category_disabled`（M06）。新增 code 时补中英翻译。

`QUOTE_VALUES_INVALID` 的 `details[].code` 由 shared 的 `validateQuoteValues()` 产生（M05，PPL 锁定 Excel 导入的行错误沿用同一组）：`required`、`too_long`（max）、`invalid_text`、`invalid_integer`、`invalid_number`、`too_many_decimals`（max）、`too_small`（min）、`too_large`（max）、`invalid_date`、`invalid_bool`、`invalid_option`（value）。`message` 是英文兜底，前端按 code 翻译（`excel.rowErrors.<code>` 已有中英文案）。M09 提交报价时合计超出 `QuoteVersion.totalAmount`（Decimal(18,2)）能存的范围也用这个错误码，报在含税总价最大的那一行的 `total_price_incl_tax` 上（`too_large`，max）。PPL 锁定 Excel 导入（`PplExcelService.parse()`）的 `EXCEL_ROWS_INVALID` 用同一组 code，`column` 是"中文 / English"列名，另有 `line_mismatch`（lineNo：这一行应对应的询价行号）、`unexpected_row`（询价行下方多出的非空行）。

- 后端统一抛 `new AppException(code, params?, details?)`，HTTP 状态码由错误码决定（`ERROR_HTTP_STATUS`，见 shared `errors.ts`），不用每次手写。全局过滤器把 ZodError 转成 `VALIDATION_FAILED`，Prisma `P2002` 转成 `CONFLICT`（`params.fields`），`P2025` 转成 `NOT_FOUND`，其他未知错误转成 `INTERNAL_ERROR` 并记录堆栈。

## 4. 校验

- 请求 schema 写在 `packages/shared/src/schemas/<模块>.ts`，命名 `createInquirySchema` + `export type CreateInquiryInput = z.infer<typeof createInquirySchema>`。
- 后端：`@Body(new ZodValidationPipe(createInquirySchema)) body: CreateInquiryInput`；查询参数同理（数字用 `z.coerce.number().int()`）。
- 前端：提交前用同一个 schema 校验，`zodErrors(schema, form)`（`apps/web/src/utils/validate.ts`）把错误映射到表单字段；服务端校验永远是最终依据。
- 字符串统一 `.trim()`；可选文本空串转 `undefined`；长度上限：名称类 100、标题 200、说明/备注 1000、意见/原因 500。
- Zod 4 写法：`.default()` 的值是**输出**值，不经过 transform（带 transform 的字段默认值写转换后的值）；枚举对象用 `z.enum(对象)`，不用 `z.nativeEnum`；需要先去空白再校验格式时写 `z.string().trim().email()`（`z.email().trim()` 会先校验再去空白）；`details[].code` 是 Zod 4 的 issue code（`invalid_type`、`too_small`、`too_big`、`invalid_format`、`invalid_value` 等）。

## 5. 鉴权与权限装饰器

| 装饰器 | 作用 |
|---|---|
| （默认） | 必须登录 + 必须是内部用户 |
| `@Public()` | 不需要登录（登录、找回/重置密码、激活、健康检查、公共配置） |
| `@AnyUser()` | 内部用户和供应商都可以（`/auth/me`、`/dicts`、`/files/*`） |
| `@SupplierOnly()` | 只允许供应商（`/api/portal/*` 整个 controller） |
| `@RequirePermissions(...codes)` | 要求全部权限码；**内部接口必须写**，只需登录的写空参数 |
| `@CurrentUser() user: AuthUser` | 取当前用户 |

数据权限和字段脱敏在 service 里做：

```ts
// 数据权限：查不到就是 404
const inquiry = await this.inquiryAccess.findOrThrow(tx, user, inquiryId);
// 列表
where: { AND: [this.scope.inquiryWhere(user), filters] }
// 脱敏
return this.fieldMask.supplier(dto, user);           // supplier.contact
return this.fieldMask.quoteValues(values, columns, user); // quote.amount
```

## 6. allowedActions

询价单、轮次、门户报价单、合同的详情接口返回 `allowedActions`，前端只按它显示操作按钮。

- 动作名在 shared 里定义为联合类型：`InquiryAction`（`edit | submit | approve | reject | cancel | editInvitees | publish | lateInvite | remind | extendDeadline | closeEarly | open | evaluate | shortlist | award | createChangeRound | editChangeRound | discardChangeRound | exportMatrix | viewAccessLog`；变更草稿轮次的动作由 `computeChangeRoundActions()` 生成，M13）、`PortalQuoteAction`（`saveDraft | submit | decline | downloadTemplate | importExcel | respondNegotiation`）、`ContractAction`（`edit | submit | review | approve | uploadSignedScan`）。
- 后端用同一个函数 `computeXxxActions(ctx)` 生成列表，动作接口里用 `assertAction(ctx, 'publish')` 复核，保证"按钮显示"和"接口放行"一致。

## 7. 事务与状态流转写法

```ts
async approve(user: AuthUser, inquiryId: string, input: ApproveInquiryInput) {
  return this.prisma.$transaction(async (tx) => {
    const inquiry = await this.inquiryAccess.findOrThrow(tx, user, inquiryId);
    const now = this.clock.now();
    const formalNo = await this.sequences.formalNo(tx, now);
    const res = await tx.inquiry.updateMany({
      where: { id: inquiry.id, docStatus: 'PENDING_APPROVAL' },
      data: { docStatus: 'APPROVED', formalNo, approvedAt: now, approvedById: user.id },
    });
    if (res.count !== 1) throw new AppException('INQUIRY_INVALID_STATUS');
    await tx.inquiryApproval.create({
      data: { inquiryId, action: 'APPROVE', comment: input.comment, actorId: user.id },
    });
    await this.mail.enqueue(tx, { type: 'APPROVAL', templateKey: 'approval.result', /* ... */ });
    await this.audit.log(tx, { actor: user, action: 'inquiry.approve', entityType: 'inquiry', entityId: inquiryId });
    return this.detail(tx, user, inquiryId);
  });
}
```

要点：先按数据权限取对象；条件更新校验期望状态；记录、邮件、审计放在同一事务；返回最新详情。

## 8. 后端代码规范

- 文件名 kebab-case（`round-state.service.ts`），类名 PascalCase，常量 UPPER_SNAKE。
- controller 不写业务逻辑；service 方法第一个参数是 `user: AuthUser`（系统任务传 `SYSTEM_ACTOR`）。
- 不写 `any`（确有必要时写 `unknown` 再收窄）；不写 `console.log`，用 Nest `Logger`。
- api 开启了 `isolatedModules` + `emitDecoratorMetadata`：出现在装饰器签名里的**纯类型**（如 `@Body() body: CreateUserInput`、`@Req() req: Request`、`@CurrentUser() user: AuthUser`）必须用 `import type` 或行内 `type` 导入，否则报 TS1272。类（`ConfigService`、各 Service）照常导入。
- Prisma 查询只 select 需要的字段；响应对象由 `toXxxDto()` 显式组装，不直接返回 Prisma 实体（避免把 `passwordHash`、`draftValues` 等带出去）。
- 金额用 `Prisma.Decimal` 或 shared 的 decimal 工具，输出前 `.toFixed(n)` 成字符串。

## 9. 前端代码规范

- 页面放 `src/views/<模块>/<页面>.vue`，PascalCase；组件 `<script setup lang="ts">`，组合式 API。
- 请求只通过 `src/api/<模块>.ts`，页面里不直接用 axios。
- 文案全部 `t('...')`，包括表格列名、按钮、提示、placeholder、确认框；枚举用 `t('enums.X.Y')`；字典/分类/PPL 标签用 `BilingualText` / `pickName()`。
- 列表页结构统一：`PageHeader` → `SearchForm` → 操作栏 → `DataTable`（分页参数和后端一致）。
- 表单：`el-form` + 提交前 zod 校验 + 服务端错误映射；危险操作用 `ElMessageBox.confirm`，需要填写原因的用带输入框的对话框。
- 日期显示统一用 `formatDateTime()`（UTC+8）；金额统一用 `formatMoney()`，被脱敏时用 `MaskedValue`。

## 10. 测试规范

- api e2e：`apps/api/test/<模块>.e2e-spec.ts`。公共工具在 `test/helpers/`：
  - `createTestApp()`：替换 `ClockService` 为 `TestClock`，`MAIL_TRANSPORT=log`，`JOBS_ENABLED=false`。
  - `resetDb()`：TRUNCATE 全部业务表；`seedBase()`：角色、字典、参数、PPL 模板集。
  - 工厂：`createUser({ role })`、`createSupplier()`、`createMaterial()`、`createApprovedInquiry()`、`publishRound()`、`submitQuote()` 等，按模块逐步补充。
  - `loginAs(app, user)`：返回带 cookie 和 `X-Requested-With` 头的 supertest agent。
- 用例名引用规则编号：`it('R06-3 驳回必须填写意见', ...)`。模块文档里的每条规则至少一个用例。
- shared / web 单元测试与源码同目录：`xxx.spec.ts`。

## 11. 代码风格与提交

- Prettier：`{ "singleQuote": true, "semi": true, "printWidth": 110, "trailingComma": "all" }`。
- ESLint：`@eslint/js` recommended + `typescript-eslint` recommended + `eslint-plugin-vue` flat/essential（格式交给 Prettier，不用含排版规则的 recommended）；`@typescript-eslint/no-explicit-any: error`；`no-console: error`（scripts、prisma 目录除外）。
