# 05 状态机与权限

状态流转表同时写进 `packages/shared/src/status.ts`（供前端显示与测试），后端由对应的领域服务执行。**表外的流转一律拒绝**（409）。

## 3. 轮次状态 `InquiryRound.status`（#23 询比价资源状态）

只有 `RoundStateService` 能改轮次状态，同时同步 `Inquiry.currentRoundStatus / currentDeadline`（I-2）。

| 当前 | 动作/事件 | 结果 | 权限 | 前置条件 | 副作用 |
|---|---|---|---|---|---|
| `DRAFT`（第 1 轮） | 发布 | `WAITING_QUOTES` | `inquiry:publish` | 询价单 `APPROVED`；受邀 ≥1 且全部启用；截止 ≥ 现在 + `inquiry.minDeadlineHours` | 冻结 `pplTemplateVersion`（当前激活的模板集）和 `pplVariantCode`（按询价单材料类别解析）；为每个受邀供应商建 `Quote(INVITED)`；`invitation` 邮件；`publishedAt/By`；审计 |
| `DRAFT`（第 N 轮，N ≥ 2） | 发布（"采购确认"，#12） | `WAITING_QUOTES` | `inquiry:publish` | 当前轮处于 `WAITING_QUOTES`/`QUOTES_CLOSED`/`OPENED`；变更原因和变更内容已填；受邀 ≥1；截止有效 | 当前轮 → `SUPERSEDED`，其报价 → `VOID`，进行中的议价关闭；`currentRoundNo = N`；冻结模板；建报价单；`change.spec` 邮件（含变更说明）；审计 |
| `WAITING_QUOTES` | 截止时间到（job） | `QUOTES_CLOSED` | 系统 | 现在 ≥ 截止 | `quotesClosedAt` |
| `WAITING_QUOTES` | 提前截止 | `QUOTES_CLOSED` | `inquiry:open` | 全部报价单已响应（`SUBMITTED` 或 `DECLINED`） | `closedEarly = true`；`quotesClosedAt` |
| `WAITING_QUOTES`/`QUOTES_CLOSED` | 延期 | `WAITING_QUOTES` | `inquiry:deadline` | 新截止 > max(原截止, 现在 + 最小小时数) | 更新截止；清空 `quotesClosedAt/closedEarly/autoReminderSentAt`；`change.deadline` 邮件给未拒绝的受邀供应商；审计 |
| `WAITING_QUOTES` | 补充邀请 | 不变 | `inquiry:invite` | 供应商启用且本轮未邀请 | 加入受邀名单；建报价单；`invitation` 邮件 |
| `WAITING_QUOTES` | 催报 | 不变 | `inquiry:remind` | 选中的报价单为 `INVITED`（未响应） | `reminder` 邮件；审计 |
| `QUOTES_CLOSED` | 开标 | `OPENED` | `inquiry:open` | — | `openedAt/By`；`SUBMITTED` → `EVALUATING`；结算积分（准时报价、快速响应、未响应）；`opening` 邮件给已提交的供应商；审计 |
| `OPENED` | 定标 | `EVALUATED` | `inquiry:award` | 中标报价为 `EVALUATING` | 见 §4、§5、M12：中标 `WON`、其余 `EVALUATING` → `LOST`；关闭进行中的议价；`evaluatedAt`、`awardedById`、`awardComment`；`Inquiry.completedAt`；建合同草稿；积分 WON；`award`/`result` 邮件；审计 |
| `DRAFT`（第 N 轮，N ≥ 2） | 放弃变更 | 删除该轮 | `inquiry:changeSpec` | — | 物理删除该轮及其行、附件挂载 |
| 非终态 | 询价单取消 | `CANCELLED` | `inquiry:cancel` | 见 §1 | — |

终态：`EVALUATED`、`SUPERSEDED`、`CANCELLED`。

**新建变更轮次**（`inquiry:changeSpec`）：询价单 `APPROVED`，当前轮处于 `WAITING_QUOTES`/`QUOTES_CLOSED`/`OPENED`，且不存在 DRAFT 轮次。复制当前轮的询价行（`sourceLineId` 指向原行）和附件挂载（新的 `InquiryFile` 指向同一个 `FileObject`），截止时间留空。当前轮在新轮发布前照常进行。

**受邀名单**（`InquiryInvitee`，询价单级别）在以下时候可编辑：第 1 轮发布前（询价单 `DRAFT`/`APPROVED`），或存在 DRAFT 变更轮次时（只影响下一轮）。补充邀请也会写入名单。

| 当前 | 动作 | 结果 | 谁 | 条件 | 副作用 |
|---|---|---|---|---|---|

## 5. 议价（#8、#30）

前置条件：轮次 `OPENED`；报价单 `EVALUATING` 且已入围（每轮最多 2 家）。

| 最近一条消息 | 允许的下一步 |
|---|---|
| 无 | 采购方 `OFFER`（创建 `Negotiation`，状态 `OPEN`） |
| 采购方 `OFFER` | 供应商 `ACCEPT` / `REJECT` / `COUNTER` |
| 供应商 `REJECT` | 采购方 `OFFER` / `CLOSE` |
| 供应商 `COUNTER` | 采购方 `ACCEPT` / `OFFER` / `CLOSE` |
| 任一方 `ACCEPT`（成交） | 采购方 `OFFER`（再议，状态回到 `OPEN`），或直接定标 |
| `CLOSE` | 无（终态） |

- `OFFER` / `COUNTER` 的 `lines` 至少有一行带 `unitPriceInclTax`、`quantity` 或 `specNote`；`REJECT` / `COUNTER` 的 `content`（原因）必填；都可带附件。
- `ACCEPT` 成交：以当前版本为底，对被接受的那条提案逐行覆盖 `unit_price_incl_tax`、`quantity`（写入报价取值作为议价数量）、把 `specNote` 追加到 `change_note`（前缀"议价第 N 轮："），重算公式列，生成 `QuoteVersion(source = NEGOTIATION)`，`negotiationMessageId` 指向这条 ACCEPT 消息；`Negotiation` → `AGREED`；`Quote.currentVersionId` 切到新版本。
- 邮件：采购方 `OFFER` → `negotiation.toSupplier`；供应商回复 → `negotiation.toBuyer`（发给询价负责人）；成交 → 双方各一封。
- 定标时自动关闭进行中的议价：追加一条系统 `CLOSE` 消息（`content = 'AUTO_CLOSED_BY_AWARD'`，前端翻译显示）。
- 议价里的价格受字段权限 `negotiation.amount` 控制。

## 7. 开标前密封与供应商隔离

### 7.1 密封（#23 补充）

| 编号 | 规则 |
|---|---|
| S-1 | 轮次处于 `DRAFT`/`WAITING_QUOTES`/`QUOTES_CLOSED` 时，内部用户通过**任何途径**都拿不到：报价取值、版本内容、合计金额、报价附件、版本备注与变更说明。能拿到：供应商、响应状态（已邀请/已查看/已提交/已拒绝）、邀请/查看/首次响应/最后提交时间、版本数、拒绝原因。 |
| S-2 | 例外：用户任一角色 code 在系统参数 `seal.preOpenViewRoles` 中（默认空，即没有任何人例外，A-02）。 |
| S-3 | 覆盖范围：响应列表、报价详情、版本详情、比价矩阵及导出、报表（询报价单统计的金额列、物流报价明细）、工作台、报价附件下载、邮件正文、审计日志。 |
| S-4 | 从未开标就被作废（`SUPERSEDED`/`CANCELLED` 且 `openedAt` 为空）的轮次永久密封。 |
| S-5 | 开标后，金额类字段再按字段权限 `quote.amount` 脱敏。 |
| S-6 | 供应商始终能看到自己报价的全部内容；永远看不到其他供应商的任何信息（包括受邀家数）。 |

### 7.2 供应商隔离（#28 权限隔离）

| 编号 | 规则 |
|---|---|
| P-1 | 门户接口一律按 `supplierId = 当前用户.supplierId` 过滤。 |
| P-2 | 供应商只能看到自己有报价单的轮次，且该轮已发布。审批前、发布前的询价对供应商不存在（#2 未审批前不可见）。 |
| P-3 | 规格文件只能访问自己有报价单的轮次的附件。 |
| P-4 | 被作废的旧轮次，供应商仍可只读查看自己当时的报价和规格（历史可查）。 |
| P-5 | 门户里不展示内部信息：项目号、草稿号、审批记录、其他供应商、内部备注。展示：正式询价号、标题、币种、说明、截止时间、轮次与变更说明、采购联系人（负责人姓名和邮箱）、公司名称。 |
| P-6 | 供应商停用后，其门户账号无法登录（`AUTH_ACCOUNT_DISABLED`），已有会话立即失效。 |

## 11. 数据权限

适用于询价单及其派生对象（轮次、询价行、附件、报价单、议价、合同、下载日志、时间线）。主数据（材料、供应商、字典）不按数据权限过滤。

| 范围 | 条件 |
|---|---|
| `ALL` | 不限 |
| `DEPT` | `Inquiry.departmentCode = 用户.departmentCode`，或满足 SELF |
| `SELF` | `ownerId`、`pdUserId`、`createdById` 之一是本人 |

用户有多个角色时取最宽范围。审批人的"待我审批"只列出其数据权限覆盖的单据。

## 12. 预置角色

定义在 `packages/shared/src/roles.ts`，seed 和测试共用。预置角色的 code 不可改、不可删，但权限可以由管理员调整（`SUPPLIER` 角色除外，其权限固定为空）。

| 角色 | 数据范围 | 功能权限 | 敏感字段 |
|---|---|---|---|
| `ADMIN` 系统管理员 | ALL | 全部 `system:*`；全部 `supplier:*`；全部 `material:*`；`inquiry:view`、`contract:view`；`stats:view`、`report:view`、`report:export`、`points:adjust` | `supplier.contact` |
| `PD` 产品开发 | SELF | `inquiry:view`、`inquiry:create`、`inquiry:spec`、`inquiry:submit`、`inquiry:changeSpec`；`material:view` | — |
| `BUYER` 采购员 | SELF | `inquiry:view`、`create`、`spec`、`submit`、`invite`、`publish`、`remind`、`deadline`、`evaluate`、`changeSpec`、`export`、`accessLog`；`supplier:view`、`manage`、`import`、`export`、`account`；`material:view`、`manage`、`import`、`export`；`contract:view`、`contract:edit`；`stats:view`、`report:view` | 全部 4 个 |
| `PURCHASE_MANAGER` 采购主管 | ALL | BUYER 的全部 + `inquiry:approve`、`open`、`award`、`cancel`；`contract:review`；`report:export`、`points:adjust`；`supplier:category:manage`、`material:category:manage` | 全部 4 个 |
| `CONTRACT_APPROVER` 合同批准人 | ALL | `inquiry:view`；`contract:view`、`contract:approve`；`stats:view`、`report:view` | `quote.amount`、`contract.amount` |
| `SUPPLIER` 供应商 | — | 无（门户接口按用户类型放行，`forSupplier = true`） | — |
