shared 包的消费方式：后端通过 workspace 依赖使用 `dist/`（CommonJS，`tsc` 构建）；前端在 `vite.config.ts` 里把 `@quoteflow/shared` 别名到 `packages/shared/src/index.ts` 直接编译源码。所以 shared 里只能写纯 TS，不能用 Node API。

TypeScript 模块设置（2026-10-20 调整）：

| 包 | module / moduleResolution | 说明 |
|---|---|---|
| `apps/api` | `NodeNext` / `NodeNext`，另开 `isolatedModules` | package.json 没有 `"type": "module"`，所以输出仍是 CommonJS；与 NestJS 11 官方模板一致 |
| `packages/shared` | `NodeNext` / `NodeNext` | 同上，`dist/` 为 CommonJS |
| `apps/web` | `ESNext` / `Bundler` | 由 Vite 打包；路径别名用 `paths`（相对 tsconfig 文件），不写 `baseUrl` |

不要再用 `moduleResolution: node10`（旧称 `node`）和 `baseUrl`：TypeScript 6.0 已把它们标为弃用（报 TS5107 / TS5101），7.0 会移除。当前配置已用 TS 5.9.3、6.0.3、7.0.2 三个版本检查通过。根目录 `.vscode/settings.json` 让编辑器使用项目自带的 TypeScript，保证编辑器提示与命令行一致。

## 3. 开发环境

### 3.1 现状

- **Docker 在另一台服务器上**：本机 Docker CLI 的默认 context `physical-host` 连接 `tcp://docker.home.arpa:2376`（TLS）。说明见 `~/docker-host/README.md`。不要安装或修改 Docker 本身。
- 远程 Docker 的两个限制（2026-10-19 实测）：
  1. bind mount 的路径由服务端解释，**本机目录不会被挂载**。只能用命名卷、`docker build` 上传构建上下文、`docker cp`。
  2. 服务端发布的端口**从本机连不上**。
- 所以采用：**依赖服务跑在远程 Docker，Node 应用跑在本机，中间用 `docker exec` 隧道连接**。PostgreSQL、SMTP、Mailpit UI 和 Prisma 建表都已经验证过。
- 只操作 `quoteflow-` 前缀的容器、卷、网络和镜像。服务器上还有别的项目，**禁止** `docker system prune`、`docker volume prune` 或删除别人的资源。

### 3.2 启动步骤

```bash
# 1. 启动远程依赖（首次会构建隧道镜像）
docker compose -f docker/compose.dev.yml up -d --build

# 2. 开隧道（长进程，单独开一个终端或后台运行；Ctrl+C 结束）
scripts/dev-tunnel.sh
#   127.0.0.1:15432 → PostgreSQL（库 quoteflow，用户 quoteflow / quoteflow_dev）
#   127.0.0.1:11025 → Mailpit SMTP
#   127.0.0.1:18025 → Mailpit Web UI（所有系统邮件都在这里看）

# 3. 本机应用
cp apps/api/.env.example apps/api/.env
npm install
npm run db:migrate          # prisma migrate dev
npm run db:seed             # 基础数据
npm run dev                 # shared(watch) + api :3000 + web :5173
```

浏览器打开 `http://127.0.0.1:5173`。Vite 把 `/api` 代理到 `http://127.0.0.1:3000`。

### 3.3 测试数据库

e2e 测试用同一个 PostgreSQL 实例里的 `quoteflow_test` 库（`DATABASE_URL_TEST`，库名必须以 `_test` 结尾，否则测试直接报错退出）。jest 的 globalSetup 执行不破坏数据的 `prisma migrate deploy`（库不存在时会自动创建）。每个测试文件开头调用 `resetDb()`（TRUNCATE 全部业务表）再插入所需夹具。**测试绝不能连 `quoteflow` 开发库。**

Prisma 会拦截 AI 代理执行的 `prisma migrate reset` 等破坏性命令，要求用户明确同意。所以 Claude 不自己运行 `npm run db:reset`；需要重置开发库时请用户执行，或征得用户明确同意。

### 3.4 排障

| 现象 | 处理 |
|---|---|
| `P1001 Can't reach database server at 127.0.0.1:15432` | 隧道没开：运行 `scripts/dev-tunnel.sh` |
| 隧道脚本报"隧道容器未运行" | `docker compose -f docker/compose.dev.yml up -d --build` |
| 隧道端口被占用 | `pkill -f "TCP-LISTEN:15432"` 后重开 |
| 看不到邮件 | 打开 `http://127.0.0.1:18025`；确认 `.env` 里 `MAIL_TRANSPORT=smtp`、`SMTP_PORT=11025` |
| 首次 `prisma generate` 慢 | 正在下载 Prisma 引擎，等待即可 |

### 4.2 请求处理链

```
helmet / cookie-parser / JSON body(1mb)
  → 全局守卫（按顺序）：CsrfGuard → SessionAuthGuard → UserTypeGuard → PermissionsGuard
  → ZodValidationPipe（body/query 用 shared 里的 schema）
  → Controller → Service（事务、状态校验、数据权限、密封、脱敏）→ Prisma
  → 全局异常过滤器（统一错误格式，见 03 §3）
```

- `req.user`（`AuthUser`）：`id、username、name、userType、locale、supplierId、departmentCode、roleCodes、permissions(Set)、fieldPermissions(Set)、dataScope`。dataScope 取用户所有角色里最宽的（ALL > DEPT > SELF）。
- 权限和用户状态**每个请求都从数据库实时加载**，不缓存、不放进 token，所以"权限变更立即生效"（#19）天然满足。用户量很小，这点开销可以忽略。

### 4.3 事务、并发与时间

- 多表写入一律放在 `prisma.$transaction(async (tx) => { ... })` 里，辅助方法接收 `tx: Prisma.TransactionClient`。
- **状态流转用条件更新防并发**：`updateMany({ where: { id, status: 期望状态 }, data })`，`count !== 1` 就抛 `ROUND_INVALID_STATUS` 等 409 错误。重复点击开标、截止瞬间提交报价、两人同时定标都靠它兜底。
- 邮件在同一个事务里写入发件箱（outbox），事务回滚就不会发出。
- "现在"一律取 `ClockService.now()`，禁止在业务代码里直接 `new Date()`。测试里替换成可控时钟，用来测截止、催报、响应时长。

### 4.4 定时任务

`@nestjs/schedule`，受 `JOBS_ENABLED` 控制（e2e 测试里关闭，改为直接调用 job 方法）。每个 job 用内存标志防止重入。按单实例部署设计；多实例需要加 PostgreSQL advisory lock，不在本期范围。

| Job | 频率 | 作用 | 模块 |
|---|---|---|---|
| `mailOutbox` | 每 30 秒 | 发送到期的待发邮件，失败按退避重试 | M02 |
| `roundDeadline` | 每分钟 | `WAITING_QUOTES` 且已过截止时间的轮次 → `QUOTES_CLOSED` | M10 |
| `autoReminder` | 每 10 分钟 | 截止前 N 小时（参数）给未响应供应商发一次催报 | M07 |
| `cleanup` | 每天 03:00（UTC+8） | 清理过期会话与令牌、超过 24 小时未被引用的上传文件 | M02 |

### 5.2 路由与权限

- 路由 meta：`{ titleKey, perm?: string | string[], userType: 'INTERNAL' | 'SUPPLIER' | 'PUBLIC' }`。
- 全局前置守卫：首次进入时调用 `GET /api/auth/me` 填充 `authStore`；未登录跳 `/login?redirect=`；用户类型不符跳到对应门户首页；缺权限跳 403 页。
- 菜单由路由表按权限过滤生成，不单独维护菜单配置。
- 按钮级权限用指令 `v-perm="'inquiry:approve'"`；**业务状态相关的按钮以后端返回的 `allowedActions` 为准**（见 03 §6），前端不重复写状态判断。

### 5.3 状态与请求

- Pinia：`auth`（me、permissions、fieldPermissions、locale、`hasPerm()`）、`dict`（按类型缓存字典，含中英名称，切语言不用重新拉）、`app`（菜单折叠等）。
- axios 实例：`baseURL: '/api'`、`withCredentials: true`、默认头 `X-Requested-With: XMLHttpRequest`（CSRF 防护要求）。响应拦截：401 → 跳登录；其他错误 → `ElMessage.error(t('errors.' + code))`，没有翻译时显示后端 message。
- 请求函数按模块放在 `src/api/*.ts`，入参和返回值类型从 `@quoteflow/shared` 导入。

### 5.4 通用组件（M00 起按需建立，后续模块复用）

| 组件 | 用途 |

## 6. 认证与会话

- 登录 `POST /api/auth/login` 成功后生成 32 字节随机 token（base64url）放进 httpOnly cookie `qf_sid`（SameSite=Lax；生产环境 Secure）。数据库 `Session.id` 只存 `sha256(token)`。
- 会话有效期取系统参数 `security.sessionHours`（默认 12），滑动续期：距上次续期超过 5 分钟才更新 `lastSeenAt / expiresAt`。
- 登出删除会话；禁用用户、重置密码会删除该用户的全部会话；修改自己的密码保留当前会话、删除其他会话。
- CSRF：SameSite=Lax，加上非 GET 请求必须带 `X-Requested-With: XMLHttpRequest`（CsrfGuard 校验）。
- 登录限流：同一 IP 每分钟 10 次，自写的 `LoginRateLimiter`（按 `ClockService` 计时，测试可控；单实例内存实现），只用在登录、找回密码接口上。
- 密码：bcryptjs，cost 10；至少 8 位，同时包含字母和数字。
- 供应商账号没有自助注册：内部人员在供应商档案里"开通门户账号"，系统发激活邮件，供应商点链接设置密码（链接 7 天有效）。找回密码同理（1 小时有效）。

## 7. 权限模型实现

码表与预置角色见 [05-状态机与权限](05-状态机与权限.md)。实现要点：

- **功能权限**：`@RequirePermissions('inquiry:approve', ...)`，要求全部满足。每个内部接口都必须声明；只需登录的接口显式写 `@RequirePermissions()` 空参数，方便审查。
- **数据权限**：`ScopeService.inquiryWhere(user)` 返回 Prisma where 条件（ALL：不限；DEPT：`departmentCode = 用户部门` 或本人相关；SELF：`ownerId / pdUserId / createdById` 之一是本人）。询价、轮次、报价、合同、下载日志的所有查询都要叠加它。查不到一律返回 404，不返回 403，避免暴露单据是否存在。
- **字段权限**：`FieldMaskService` 统一脱敏，被脱敏的字段值置为 `null`，响应里带 `maskedFields: string[]`，前端用 `MaskedValue` 显示。
- **用户类型**：UserTypeGuard 默认只放行内部用户，供应商访问返回 403。`/api/portal/*` 用 `@SupplierOnly()`；两类用户都要用的接口（`/api/auth/me`、`/api/dicts`、`/api/files/*` 等）用 `@AnyUser()`；登录、找回密码等用 `@Public()`。
- **供应商数据**：门户接口的查询条件一律带 `supplierId = req.user.supplierId`。

## 8. 开标前密封实现

规则见 05 §7，实现要点：

- `SealService.canViewQuoteContent(user, round)`：轮次 `OPENED / EVALUATED` → 可看（再叠加字段脱敏）；`SUPERSEDED / CANCELLED` 且 `openedAt` 非空 → 可看；其余（`DRAFT / WAITING_QUOTES / QUOTES_CLOSED`，以及从未开标就被作废的轮次）→ 只有用户角色在系统参数 `seal.preOpenViewRoles`（默认空数组）里才可看。
- 所有返回报价内容的地方（报价详情、版本、比价矩阵、导出、报表、报价附件下载、邮件正文、操作日志）都必须经过它。密封时只返回：供应商、响应状态、邀请/查看/提交时间、版本数。
- M10 有一组专门的 e2e 测试，逐个接口验证密封，任何新接口返回报价数据都要加进这组测试。

## 9. 文件存储与预览

- 存储驱动接口 `StorageDriver { put, getStream, delete, exists }`。本期实现 `local`（`STORAGE_DIR`，默认 `apps/api/storage/`，已加入 .gitignore），路径 `yyyy/mm/<cuid>.<ext>`。S3 兼容驱动等部署确定后再做（A-20）。
- 上传 `POST /api/files`（multipart，字段 `file` + `kind`）：multer 内存存储 → 按 kind 校验扩展名、**魔数**和大小 → 计算 sha256 → 写入存储 → 建 `FileObject`。此时文件还没挂到任何业务对象上。
- 下载/预览只有一个入口 `GET /api/files/:id/content?disposition=inline|attachment`，由**访问策略注册表**决定能否访问：各模块注册解析器（询价附件、通用附件、材料图片、合同扫描件），解析器根据文件被谁引用判断权限，并决定是否写 `FileAccessLog`。没有任何解析器放行时，只有"上传者本人且文件尚未被引用"可以访问，其余 403。
- xlsx 预览：`GET /api/files/:id/sheet-preview` 用 ExcelJS 读出每个 sheet 前 200 行 × 50 列，返回 JSON，前端渲染只读表格。xls / docx 只支持下载。
- 文件名用 RFC 5987 `filename*` 编码，保证中文名正常下载。

## 10. 邮件

- `EmailMessage` 表同时是发件箱和发送记录（#4 "邮件通知记录"页面）。
- `MailService.enqueue(tx, { type, templateKey, language, to, cc, data, supplierId?, userId?, inquiryId?, bizKey? })`：**入队时就渲染**好 subject/html/text 存下来，日志里看到的就是实际发出的内容。`bizKey` 唯一，用来防重复（比如自动催报）。
- 发送任务每 30 秒取最多 20 封到期邮件，用 Nodemailer 发送。失败按 1、5、15、60、180 分钟退避重试，5 次后标记 `FAILED`，管理员可在邮件记录页重发。
- `MAIL_TRANSPORT=smtp`（开发连 Mailpit，生产连真实 SMTP）或 `log`（只写日志并标记 SENT，e2e 测试用）。
- 语言：供应商按 `Supplier.preferredLanguage`（zh-CN / en-US / bilingual），内部用户按 `User.locale`。bilingual 时主题为"中文 / English"，正文中文段在上、英文段在下。
- 模板写在代码里（`infra/mail/templates/*.ts`），每个模板导出 zh-CN 和 en-US 两个渲染函数。本期不做后台可编辑的邮件模板。
- 邮件里的时间统一写成 `2026-11-20 17:00（北京时间 UTC+8）` / `2026-11-20 17:00 (Beijing Time, UTC+8)`。链接基于 `APP_BASE_URL`。

## 11. Excel

- 统一用 ExcelJS。两类模板：
  1. **标准模板**（#29：材料、供应商、询价行）：`ExcelTemplateService`（M02）。表头写"中文 / English"，导入时表头必须与模板**名称和顺序完全一致**，否则整表拒绝并列出缺少列、多余列、顺序错误。行数据先全部校验，有任何错误就整表不导入并返回错误清单（第几行、哪一列、原因）。不做任何智能识别。
  2. **锁定报价模板**（#6）：`PplExcelService`（M05）。工作表保护 + 隐藏签名元数据，格式见 [04-PPL模板规范](04-PPL模板规范.md) §7。
- 上限：单文件 10MB、5000 行。

## 12. 多语言（#18）

- 前端 vue-i18n（`legacy: false`），文案按模块拆在 `locales/zh-CN/*.ts` 与 `locales/en-US/*.ts`。键命名 `模块.页面.元素`，如 `inquiry.list.title`、`common.actions.save`、`enums.RoundStatus.OPENED`、`errors.QUOTE_SEALED`。
- 切换语言：顶栏切换 → `authStore.setLocale()` 修改 i18n locale、Element Plus locale（`el-config-provider`）、dayjs locale，并调用 `PUT /api/auth/me/locale` 保存到账号。不刷新页面、不重建路由组件，所以**正在编辑的表单不会丢**（验收点"即时切换不丢单据"）。登录页语言存在 localStorage。
- 业务数据双语：字典、材料分类、PPL 列标签都存 `nameZh/nameEn`（或 `labelZh/labelEn`），用 `BilingualText` 或 `pickName()` 按当前语言显示，英文为空时回退中文。
- 后端只返回错误码和参数，不返回翻译后的文案（邮件除外）。
- 防遗漏：`scripts/check-i18n.mjs` 扫描 `apps/web/src`（排除 `locales/`），发现 `.vue`/`.ts` 里有中日韩字符就失败；web 的单元测试检查 zh-CN 和 en-US 的键集合完全一致。

## 13. 编号、金额、时间

- 编号（`SequenceService.next(key)`，`INSERT ... ON CONFLICT DO UPDATE ... RETURNING` 原子自增；日期按 UTC+8 取）：

| 编号 | 格式 | 计数周期 |
|---|---|---|
| 询价草稿号 | `DR-20261026-0001` | 每天 |
| 正式询价号 | `RFQ-202610-0001` | 每月 |
| 合同号 | `CT-202611-0001` | 每月 |
| 材料编码 | `MAT-000001` | 全局 |
| 供应商编码 | `SUP10001`（从 10001 起） | 全局 |

- 金额：数据库 `Decimal`（单价 18,4、合计 18,2），API 和 PPL 取值里一律用**字符串**（`"12800.00"`）。计算只用 shared 里基于 decimal.js 的函数，四舍五入用 ROUND_HALF_UP。**禁止用 JS number 做金额运算。**
- 时间：数据库 `timestamptz` 存 UTC；API 传 ISO 8601 字符串；界面和邮件按 `Asia/Shanghai` 显示，截止时间旁注明"UTC+8"。截止时间选择器按 UTC+8 输入。

## 14. 审计日志

- `AuditService.log(txOrPrisma, { actor, action, entityType, entityId, summary, detail, ip })`。action 用 `实体.动词`：`inquiry.submit`、`round.open`、`quote.submit`、`role.update` 等。
- 关键动作都要记：登录/登出、用户与角色变更、字典与参数变更、询价单全部状态流转、发布、催报、截止变更、开标、入围、议价每一步、定标、合同流转、积分手工调整、文件导入。
- **审计内容里不能出现报价金额。** 报价提交只记"提交了第 N 版"。
